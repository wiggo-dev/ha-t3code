# Cursor credential schema and Provider home

Phase 2 auth uses an optional add-on `cursor_api_key` (`password?`) mapped to `CURSOR_API_KEY`, with login-file fallback under Provider home `/data/home` via `XDG_CONFIG_HOME=/data/home/.config` (so Cursor tokens land at `/data/home/.config/cursor/auth.json` and future Providers share that tree). Process `HOME` is the Workspace `/config` so `~` and default folders stay on Home Assistant config; T3 state stays `/data/t3`. We do not mutate T3's settings SQLite to flip Cursor on: inject auth every start, log when ready, and let the operator enable Cursor once in T3 Settings (never force-enable over an explicit disable). API key wins when both key and login file are present. We rejected a Cursor-branded `/data/cursor` home, setting `HOME=/data/home` (that made `~` leave `/config`), and auto-editing T3 SQLite because multi-Provider CLIs share XDG state under Provider home, operators expect `~` to mean the Workspace, and T3 settings shape is version-fragile.
