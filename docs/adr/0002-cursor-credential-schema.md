# Cursor credential schema and Provider home

Phase 2 auth uses an optional add-on `cursor_api_key` (`password?`) mapped to `CURSOR_API_KEY`, with login-file fallback under process `HOME=/data/home` (so Cursor tokens land at `/data/home/.config/cursor/auth.json` and future Providers share a neutral home). Workspace stays `/config` and T3 state stays `/data/t3`. We do not mutate T3's settings SQLite to flip Cursor on: inject auth every start, log when ready, and let the operator enable Cursor once in T3 Settings (never force-enable over an explicit disable). API key wins when both key and login file are present. We rejected a Cursor-branded `/data/cursor` home and auto-editing T3 SQLite because multi-Provider CLIs will share `HOME`, and T3 settings shape is version-fragile.
