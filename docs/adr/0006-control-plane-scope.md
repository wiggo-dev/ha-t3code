# Live HA control-plane stays thin; no OpenCode MCP

After thin-log evidence (ADR-0005), the permanent supported agent workflow is **file edits under `/config` + read-only Core/Supervisor REST + operator executes reloads, restarts, and device actions in the HA UI**. We do **not** ship OpenCode’s MCP server (`ha-mcp`), `zigporter`, screenshot/headless-browser tooling, or an Add-on-maintained bridge to HA native `/api/mcp/assist` (operators may wire native MCP into Cursor themselves). An optional later effort may add `hab` for configuration-assist only (automations/scripts/dashboard helpers and a whitelist of config reloads — not arbitrary device control, backups/restore, or Core/OS/add-on updates). That later effort is outside this map’s destination. We reject OpenCode-style full control-plane parity because this Add-on is T3 + Cursor + Skills, not an OpenCode fork, and the destination is evidence-backed suggestions without paste-dumping — not autonomous home administration.
