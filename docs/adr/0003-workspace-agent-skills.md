# Ship Home Assistant Skills under Workspace `.agents/skills`

Phase 2 Skills use one Workspace tree, `/config/.agents/skills/<name>/SKILL.md`, for both the five bundled Home Assistant Skills and operator-added user Skills so Server-side Cursor (and other Providers that understand Agent Skills) discover them without OpenCode-only `.opencode/` paths. The Add-on bakes the five into the image and digest-syncs them into that tree on start: deploy if missing, refresh if still byte-identical to what we last wrote, preserve and warn if the operator edited them; digest state lives on persistent `/data`, not in the Workspace. We accept that bundled Skills therefore appear in Home Assistant `/config` backups and git. Skill bodies are light-adapted from OpenCode (keep HA procedures; strip or rewrite MCP/`hab` assumptions we are not shipping — ADR-0006). We rejected OpenCode’s split (bundled under `/data` config + user under `.opencode/skills/`), dual `.agents`+`.cursor` trees, Provider-home-only globals, seed-once-never-update, and verbatim upstream text, because one portable Workspace path plus upgrade-safe user-wins sync matches T3/Cursor discovery and HA backup habits better than mirroring OpenCode’s layout.
