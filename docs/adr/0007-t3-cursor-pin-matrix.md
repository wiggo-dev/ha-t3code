# Pin t3 and Cursor together; Add-on release is the upgrade

ACP skew between `t3` and `cursor-agent` is the failure that takes Server-side Cursor down, so one Add-on image is a **pin matrix**: both versions baked at build (npm `T3_VERSION` + Cursor lab tarball URL and checksums), Cursor auto-update disabled via a PATH wrapper that injects `--disable-auto-update` (T3’s ACP spawn does not pass the flag). Operators change the matrix only by Add-on Update/Rebuild; previous Add-on version is break-glass. Maintainers refresh both pins together with `scripts/bump-pins.sh` (read `t3@latest` + lab version from the install script, write pins/checksums, patch-bump `config.yaml`, CHANGELOG) then commit and push — on-demand, never a scheduled auto-PR. Startup logs `t3 --version` and `cursor-agent --version` next to the Add-on version. We rejected status-quo Cursor float, `t3@latest`/`nightly` at build, and runtime `agent update` because those ship an unknown pair and leave no rollback target.
