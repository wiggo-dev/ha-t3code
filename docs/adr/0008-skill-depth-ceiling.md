# Skill depth ceiling: gather and propose, operator applies

ADR-0005/0006 define thin evidence sources and a permanent thin control plane; this ADR sets how deep Home Assistant Skills may go so implementing thin logs does not reopen either. For runtime diagnosis, Skills prefer the Workspace file baseline, then thin Core/Supervisor REST when files are not enough, then operator paste or `/config/.t3code/exports/` if REST is unavailable — never paste-dumping as the happy path, and never blocking a file-backed proposal when live evidence is missing. Pure configuration/improvement work (nothing broken) may recommend from files and docs alone; when thin REST is up and a draft names entities, Skills should recommend (not require) a quick existence/state check. All five bundled Home Assistant Skills encode the same loop — ask → agent gathers thin evidence → propose the smallest change → operator approves edits and applies reload/restart/UI — and never instruct service calls, reload, restart, or device control. Skills name the ADR-0005 tiers and when to use them; they do not embed long `curl` recipes (those land with thin-log plumbing in DOCS or a short shared note).
