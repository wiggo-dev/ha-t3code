# Thin log and evidence sources without full MCP

Server-side Cursor needs live evidence for troubleshooting without operator paste-dumping, but not OpenCode MCP / `hab` parity. We adopt a **three-tier** source set: (1) **file baseline** under the Workspace — `home-assistant.log`, `.HA_VERSION`, read-only `.storage/` registries, and the full YAML tree via `grep`/`yq`/`jq`; (2) **Home Assistant Core REST** via `homeassistant_api: true` and `SUPERVISOR_TOKEN` — read-only `curl`+`jq` for states, history, logbook, and error log (no `ha` CLI); (3) **Supervisor REST** via `hassio_api: true` — read-only access to `/core/logs`, `/addons/{slug}/logs`, `/resolution/info`, and host/supervisor health endpoints. Operators may also drop exports in `/config/.t3code/exports/` (documented, gitignored). Explicitly **out of scope for this Add-on** ([ADR-0006](0006-control-plane-scope.md)): MCP server parity (`hab`, `zigporter`, `write_config_safe`, screenshots), service calls / reload / restart from the agent, HA native `/api/mcp/assist` consumption from T3, and recorder DB queries (no `sqlite3` in the image). Skills stay read-only during investigation; API use is evidence-gathering only.
